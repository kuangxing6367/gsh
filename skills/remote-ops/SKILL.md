# 远程节点巡检

用于回答「这台/这几台机器现在什么状态」。全程只读，不做任何写操作。

## 步骤

1. 确认节点名。可用节点来自 `config.json` 的 `plugins_cfg.tools.remote.nodes`，
   当前常见的是 `rzsh`（ARM 实验机），以及你在配置里自行添加的 `139` / `160`。
2. 对每个节点各调一次 `bash` 工具，**必须带 `node` 参数**：

```json
{"command": "hostname; uname -m; uptime; free -m | head -2; df -h / | tail -1", "node": "rzsh"}
```

3. 一次调用里用 `;` 串起多条命令，减少往返次数——每次远程调用都有连接开销。
4. 汇总成表：主机名 / 架构 / 负载 / 内存 / 根分区使用率。

## 判断口径

- 负载看 1 分钟值是否超过核数（`nproc`），不要只看绝对值。
- 根分区 > 85% 视为需要处理，> 95% 视为告警。
- 内存看 `available` 而不是 `free`，Linux 会把空闲内存拿去做缓存。

## 不要做

- 不要在这些节点上跑 `rm`、`mkfs`、`systemctl restart` 之类的写操作，
  除非用户明确要求。安全策略会把 `rm -r` 判为受限命令并拦截。
- 不要假设所有节点都是 x86：`rzsh` 指向的是 aarch64 机器，
  任何依赖架构的结论（二进制能否运行）都要先看 `uname -m`。
